# Contributing to PEPCB

Thank you for your interest in contributing to **PEPCB**!  
We welcome all kinds of contributions, from bug fixes and new features to documentation and discussions.

---

## 📌 Ground Rules

1. **Be Respectful**  
   Treat all contributors with respect and professionalism.

2. **Keep It Clean**  
   Write clean, modular, and well-documented code.

3. **One Thing at a Time**  
   Each pull request (PR) should focus on a single issue or feature.

4. **Write Tests (If Applicable)**  
   If you add or modify logic-heavy code, please include tests.

5. **Stay in Sync**  
   Before starting major work, check open issues or create one to discuss your idea.

---

## 🛠️ How to Contribute

### 1. Fork the Repository

Click the "Fork" button on GitHub, then clone your fork locally:

```bash
git clone https://github.com/yourusername/PEPCB.git
cd PEPCB
```

### 2. Create a Branch

```bash
git checkout -b your-feature-name
```

### 3. Make Your Changes  
Edit code, add tests/docs, and commit:

```bash
git add .
git commit -m "Describe your changes"
```

### 4. Push to GitHub

```bash
git push origin your-feature-name
```

### 5. Open a Pull Request

Go to your fork on GitHub and click **"Compare & pull request"**.

---

## 🧪 Code Style & Guidelines

- C++: Use consistent formatting (e.g., 2- or 4-space indent, no tabs).
- Python: Follow [PEP8](https://pep8.org/).
- Use clear names and include comments where needed.
- UI code should be modular and platform-agnostic where possible.

---

## 🤖 Contributions We Love

- Bug fixes and performance improvements
- New features (parasitic models, layout strategies, UI tools, etc.)
- Plugin enhancements for EDA tools
- Documentation: examples, explanations, diagrams
- Testing and validation tools
